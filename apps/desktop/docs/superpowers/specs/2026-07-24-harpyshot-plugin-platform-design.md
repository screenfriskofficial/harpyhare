# Платформа плагинов + harpyshot (первый плагин)

Дата: 2026-07-24
Статус: утверждён пользователем (платформа-first · sidecar-процессы · ad-hoc-подпись)

## Цель

Ввести в десктоп-приложение **платформу нативных плагинов**. Плагин — отдельный
подписанный бинарь (sidecar), которым управляет хост через stdio/JSON. Плагины
живут в **отдельном монорепозитории** `harpyhare-plugins` (структура как
`desktop`/`landing`), собираются в артефакты, **автоматически подкачиваются на
старте один раз**, кэшируются; выход новой версии **подсвечивается** во вкладке
«Плагины». Внутри приложения плагин можно **включить/выключить** и назначить ему
хоткей; включённый плагин рисует иконку в тулбаре под чатом (`ComposerToolbar`).

Первый плагин — **harpyshot** (на C): по хоткею (дефолт ⌘⇧S) даёт выделить зону
экрана, скринит её и **автоматически кладёт скриншот во вложения текущего
черновика чата**.

Важное расцепление: сама фича harpyshot (регион-скрин → вложение) не требует
плагинной инфраструктуры — её отгрузил бы шелл-аут в `screencapture -i` из
хоста. «Нативный плагин с автозагрузкой» — это архитектурная цель пользователя,
и именно она формирует объём. Фича — первый житель платформы, а не наоборот.

## Подтверждённые решения (из брейншторминга)

1. **Платформа-first.** Строим нативный ABI + распространение + автозагрузку/
   апдейты; harpyshot — первый внешний плагин против этого ABI.
2. **Модель исполнения — sidecar-процесс.** Плагин = отдельный бинарь; хост
   спавнит и общается по stdio/JSON. Не in-process dylib (нет library-validation,
   изоляция падений, чистая подпись) и не «хост держит привилегию».
3. **«На C» = C-ABI как контракт, а не обязательно исходники на C.** Плагин можно
   писать на C/C++/Rust; harpyshot — на C. Протокол языконезависим.
4. **Контракт v1 = `attachment_source`.** Плагин активируют (хоткей/иконка), он
   возвращает 0–1 вложение (image/text) в черновик активного чата. Богатое
   (своя UI-панель, чтение состояния чата, стриминг) — расширение ABI позже.
5. **Подпись — ad-hoc (`codesign -s -`).** Developer-ID/нотаризации нет. Следствия
   для TCC — см. раздел «Подпись и TCC».
6. **Хостинг — GitHub Releases** репо `harpyhare-plugins` + minisign (консистентно
   с апдейтером приложения и чтением релизов лендингом).
7. **Дефолты:** свежескачанный плагин **выключен** (opt-in; глобальный ⌘⇧S не
   перехватывается без ведома пользователя). Начальная установка артефактов —
   авто (один раз); **обновления не применяются молча** — подсвечиваются и
   применяются кнопкой «Обновить».
8. **Иконка плагина — имя lucide-иконки** из манифеста (безопасно, монохром на
   палитре). Кастомный SVG — позже, с санитайзингом.

## Компоненты

### Хост-рантайм (`src-tauri/src/plugins.rs`, новый модуль)

Обнаружение установленных плагинов, спавн sidecar, протокол, кэш, фоновая
загрузка/апдейт-чек. Доменная логика (парс/валидация манифеста, парс результата
протокола, diff индекса) — чистая и юнит-тестируемая в `plugins/tests.rs`
(child-модуль, как у остальных). Tauri-команды владеет тот же модуль и добавляет
их в `collect_commands!` в `bindings.rs`.

### Кэш и реестр

```
~/Library/Application Support/com.audioservice.helper/plugins/
  <id>/<version>/plugin.json + <bin>     # распакованный плагин
  installed.json                         # { "<id>": "1.0.0" } активная версия на плагин
```

Рантайм-реестр: `Vec<InstalledPlugin { manifest, dir, update_available: Option<String> }>`
— источник для `list_plugins`, **не Settings**. Settings хранит только
пользовательские префы (вкл + хоткей).

### Манифест `plugin.json`

Статический файл рядом с бинарём; **host читает его, не запуская код** (перечисление
плагинов без исполнения недоверенного бинаря).

```json
{ "schema": 1, "id": "harpyshot", "name": "harpyshot",
  "description": "Скриншот выделенной зоны во вложение", "version": "1.0.0",
  "icon": "crop", "capability": "attachment_source",
  "default_hotkey": "Cmd+Shift+S", "min_host_version": "0.9.0",
  "bin": { "aarch64": "harpyshot-aarch64", "x86_64": "harpyshot-x86_64" } }
```

Валидация host'ом при загрузке в реестр: `id ~ ^[a-z0-9-]+$`; `version`/
`min_host_version` — semver; `capability` из известного набора (`attachment_source`);
`default_hotkey` парсится `hotkey::parse_hotkey`; `icon` — из allowlist
lucide-имён; `bin` содержит ключ текущей архитектуры. Невалидный манифест →
плагин игнорируется с eprintln, реестр не падает.

### Протокол host↔sidecar (stdio/JSON, один раунд)

- host → stdin: `{"protocol":1,"action":"activate"}\n`
- sidecar → stdout (ровно одна строка JSON) и завершение:

```
{"protocol":1,"kind":"image","media_type":"image/png","data_base64":"…"}
{"protocol":1,"kind":"text","text":"…"}
{"protocol":1,"kind":"none"}                      // отмена (Esc и т.п.)
{"protocol":1,"kind":"error","message":"…"}
```

Инварианты: активация **человекопаз** (выделение зоны может длиться десятки
секунд) — host НЕ ставит короткий таймаут, а ждёт выхода процесса; жёсткий
ceiling — только как reaper зависшего процесса (несколько минут) + `kill`.
Повторная активация того же плагина, пока предыдущая жива, игнорируется (одна
активация на плагин). `stderr` плагина уходит в лог с префиксом `[plugin:<id>]`;
неразобранный/лишний stdout → трактуется как `error`. Host до инъекции валидирует `media_type ∈ SUPPORTED_IMAGE_TYPES`
(`lib/composer` зеркалит набор) и предельный размер (защита от гигантского base64).
Версия `protocol` позволит эволюцию без слома старых плагинов.

## Поток 1 — активация (harpyshot)

1. Глобальный хоткей плагина срабатывает (регистрируется host'ом по жизненному
   циклу HUD — как PTT/toggle/суфлёр).
2. `plugins::on_activate(app, id)` (через `defer`, инвариант реестра хоткеев):
   найти установленный **включённый** плагин → спавн sidecar (`spawn_blocking`)
   → отправить `activate` → прочитать результат с таймаутом → валидация.
3. `image` → host эмитит `plugin-result {pluginId, kind:"image", mediaType, dataBase64}`
   и делает `show + set_focus` HUD.
4. Фронт (хук `usePlugins`) слушает `plugin-result` → строит `File` из base64 →
   **новый метод `chats.addDraftImage(activeId, dataUrl, mediaType)`**, который
   переиспользует существующий `fileToAttachment` (даунскейл >5 МБ, `toImagePayload`)
   → вложение падает в `draftAttachments` активного чата.

Переиспользование конвейера вложений обязательно: screenshot не заводит своей
ветки даунскейла/лимитов — идёт ровно тем же путём, что вставка/дроп картинки.

## Поток 2 — старт и апдейты

1. Старт: host читает кэш-реестр (`installed.json` + манифесты) → мгновенно отдаёт
   `list_plugins` (сеть не в критическом пути).
2. Фон: фетч индекса `plugins.json` из GitHub Releases (с `User-Agent`, как все
   reqwest-клиенты) → diff с кэшем:
   - плагина нет в кэше → **скачать авто (один раз)** + verify + установить;
   - установлен, но `index.version > installed` → пометить `update_available`,
     **не применять**;
   - `min_host_version > текущей` → пропустить.
3. `plugins-changed` → фронт перечитывает `list_plugins` → вкладка «Плагины»
   показывает бейджи (загружается / обновление доступно).

## Settings-контракт, команды, события

### Settings

Новое поле (по образцу `prompt_presets`):

```rust
pub struct PluginSetting { pub id: String, pub enabled: bool, pub hotkey: String }
// в Settings:
pub plugin_settings: Vec<PluginSetting>,   // default: пусто
```

- `DEFAULT_SETTINGS` в `ipc/types.ts` берёт **копию** `[...SETTINGS_DEFAULTS.plugin_settings]`
  (specta печатает константу `as const` → `readonly`, а поле изменяемое — тот же
  инвариант, что у `prompt_presets`).
- `contract.test.ts` получает `SameShape<PluginSetting, Rust.PluginSetting>`.
- Мердж реестр×префы: у установленного плагина нет записи в `plugin_settings` →
  дефолт `enabled=false`, `hotkey=manifest.default_hotkey`. Первое сохранение
  материализует запись.
- Счётчик «Settings (31 поле)» в `apps/desktop/CLAUDE.md` → **32**, добавить абзац
  про `plugin_settings` в раздел Settings.

### Команды (в `plugins.rs`, регистрируются в `collect_commands!`)

- `list_plugins() -> Vec<PluginDescriptor>` — `{id, name, description, version, icon, capability, enabled, hotkey, state}`, где `state ∈ {ready, downloading, update_available}`. Собирается из реестра + `plugin_settings`.
- `activate_plugin(id: String)` — клик по иконке в тулбаре (то же, что хоткей).
- `check_plugin_updates()` / `update_plugin(id: String)` — Ф3.

Вкл/выкл и смена хоткея идут **штатным путём через `set_settings`** (автосейв draft
лаунчера), а не отдельными командами — как остальные хоткеи. Rust на изменении
`plugin_settings` перерегистрирует хоткеи плагинов.

### События (`events.rs`, типизированные хелперы)

- `plugins-changed` (payload `()`) — реестр обновился (скачано/обновлено/статус).
- `plugin-result` — `{pluginId, kind, mediaType?, dataBase64?, text?, message?}`.

Оба типа перечислить в `.typ::<>()` в `bindings.rs` (событийные типы не
подхватываются автоматически). `EventMap` в `ipc/types.ts` — соответствующие
записи.

## Хоткеи (жизненный цикл HUD)

`register_plugin_hotkeys(app, settings, registry)` внутри
`window::register_main_window_hotkeys`: для каждого установленного **включённого**
плагина с валидным хоткеем — `on_shortcut`, на `Pressed` → `defer(move → plugins::on_activate(app, id))`.
Снятие в `stop_main_window` (расширить `unregister_main_window_hotkeys`),
перерегистрация в `set_settings` (расширить `preferences::reregister_changed_hotkeys`,
который уже ранне-выходит без main-окна — автосейв из лаунчера не трогает
глобальную регистрацию).

**Конфликт ⌘⇧S:** как глобальный, он перехватывает «Сохранить как» у активного
приложения, пока HUD запущен. Осознанно: дефолт по запросу пользователя,
настраивается; плагин по умолчанию выключен, поэтому перехвата нет, пока
пользователь сам не включит harpyshot.

## Распространение (Ф2) и реальность ad-hoc

Монорепо `harpyhare-plugins`: `plugins/harpyshot/` (исходники C + сборка), общий
релиз-скрипт. Скрипт: сборка per-arch (`aarch64`, `x86_64`) → **`codesign -s -`
каждого бинаря** (обязательно: на Apple Silicon неподписанный executable
убивается ядром) → **minisign** каждого артефакта → сборка индекса `plugins.json`
→ GitHub Release.

```json
{ "schema": 1, "plugins": [
  { "id":"harpyshot", "version":"1.0.0", "min_host_version":"0.9.0",
    "manifest_url":"https://…/plugin.json",
    "bin": { "aarch64": {"url":"https://…/harpyshot-aarch64","sig_url":"https://…/harpyshot-aarch64.minisig"},
             "x86_64": {"url":"https://…/harpyshot-x86_64","sig_url":"https://…/harpyshot-x86_64.minisig"} } } ] }
```

Host-скачивание: бинарь + манифест → **minisign-verify** (публичный ключ вшит в
хост константой, как pubkey апдейтера) → запись в `plugins/<id>/<version>/` →
обновить `installed.json`. Файл пишется `reqwest`'ом, **без `com.apple.quarantine`**
→ Gatekeeper не блокирует запуск скачанного sidecar. Бинарь после скачивания
**не модифицируется** (сохраняем cdhash/ad-hoc-подпись). minisign даёт
авторство/целостность; ad-hoc codesign — исполнимость на arm64.

## Подпись и TCC

harpyshot нужен доступ «Запись экрана». Определяющая неизвестность: **требует ли
интерактивный `screencapture -i` TCC-грант от вызывающего sidecar** на текущих
macOS, или Apple делает захват под своей личностью.

- Если **не требует** — TCC-проблема снята полностью (ad-hoc не важен для
  screenshot-пути).
- Если **требует** — при ad-hoc-подписи грант ключуется по cdhash, и каждое
  обновление harpyshot может **переспросить «Запись экрана»**. Мягкая деградация:
  реже апдейтить бинарь + однострочная заметка в UI при обновлении.

Проверка этого — **проба №1** в плане реализации (см. Риски).

## Апдейты (Ф3)

`update_plugin(id)`: скачать более новую версию → verify → переключить
`installed.json` на неё → `plugins-changed`. UI: бейдж «обновление доступно» +
кнопка «Обновить». Старые версии в кэше можно подчищать best-effort.

## harpyshot (C-sidecar)

`plugins/harpyshot/harpyshot.c`:

1. Прочитать stdin (наличие `activate` достаточно; на v1 можно игнорировать тело).
2. `posix_spawn` → `/usr/sbin/screencapture -i -x /tmp/harpyshot-<pid>.png`
   (`-i` интерактивный крест выделения, `-x` без звука затвора). UI выделения
   рисует сам `screencapture` — ObjC/Cocoa не нужны, код честно на C.
3. Файл существует и непуст → прочитать → base64 → печать
   `{"protocol":1,"kind":"image","media_type":"image/png","data_base64":"…"}`.
4. Файла нет (пользователь нажал Esc/отменил — `screencapture` возвращает 0, но
   ничего не пишет) → `{"protocol":1,"kind":"none"}`.
5. Удалить temp-файл.

Компиляция clang, ad-hoc-подпись в релиз-скрипте.

## UI

### Лаунчер

- Таб `plugins` в `LAUNCHER_TABS` (`tabs.ts`, иконка `Puzzle`), кейс в `TabBody`
  (`TabContent.tsx`).
- `PluginsPanel`: список из `list_plugins` — имя, описание, версия; тумблер
  (`enabled` → `plugin_settings`); `HotkeyCapture` (переиспользовать существующий);
  бейджи `downloading` / `update_available` + кнопка «Обновить». Пустое состояние,
  пока ничего не скачано.

### HUD

- В `ComposerToolbar` включённые `attachment_source`-плагины рендерятся
  иконками-кнопками рядом с существующими (Eraser / NotebookText / Параметры).
  Иконка — lucide-компонент по имени из манифеста через allowlist-реестр
  (`icon` → компонент). Клик → `activate_plugin(id)`.
- Палитра: иконки монохромные `text-foreground` (правило «primary не как цвет
  текста/иконок» — primary только для индикаторов/заливок).

## Порядок фаз (один дизайн, поэтапная реализация)

- **Ф1 — ядро, локально, без сети.** Хост-рантайм + протокол + манифест +
  Settings-контракт + UI-каркас (таб + слот иконки в тулбаре) + harpyshot-sidecar,
  собираемый локально и кладущийся в кэш вручную. harpyshot работает end-to-end.
  Здесь же — **проба №1** (`screencapture -i` + TCC).
- **Ф2 — распространение.** Монорепо `harpyhare-plugins` + релиз-скрипт (сборка →
  ad-hoc codesign → minisign → индекс → GitHub Release) + хостовая автозагрузка/
  verify/кэш на старте.
- **Ф3 — апдейты.** Детекшн версий + бейджи + «Обновить».

## Тестирование

- **Rust (`plugins/tests.rs`):** парс + валидация манифеста (валидные/битые/
  неизвестный capability/невалидный hotkey/чужая арх.); парс результата протокола
  (все `kind` + мусор); diff индекса ↔ кэша (нет/новее/старее/`min_host_version`);
  мердж реестр×`plugin_settings`.
- **Фронт:** `usePlugins` (`plugin-result` image → вложение через `addDraftImage`);
  contract-тест формы `PluginSetting`; рендер `PluginsPanel` (тумблер/бейджи);
  allowlist-реестр иконок.
- Смоук harpyshot-sidecar — вручную (интерактивный `screencapture`).

## Риски и ранние пробы

1. **TCC у `screencapture -i` (проба №1, блокирующая).** Определяет всю
   TCC-историю; делать первой в Ф1 на реальной машине.
2. **Глобальный перехват ⌘⇧S** пока HUD запущен — ожидаемо; смягчено дефолтным
   выкл-состоянием плагина.
3. **ad-hoc переспрос «Запись экрана» при апдейте** — только если проба №1
   покажет, что грант нужен вызывающему.
4. **Резолв пути sidecar** из кэша `Application Support` (не из бандла) — единый
   путь в dev и prod, дырок нет.
5. **Большой Retina-PNG** — снимается переиспользованием даунскейла конвейера
   вложений (>5 МБ → JPEG).
6. **Спавн/таймаут sidecar** — «зависший» плагин не должен вешать хост: жёсткий
   таймаут + `kill`, ошибки не роняют приложение.

## Зафиксированные умолчания (можно пересмотреть)

- Плагин после скачивания **выключен** до явного включения.
- Обновления **не** авто-применяются — только подсветка + ручная кнопка.
- Иконка — **имя lucide**, не произвольный SVG (v1).
- Один результат на активацию (0–1 вложение); мульти-вложение — позже.
